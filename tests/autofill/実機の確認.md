# 実機の確認手順(フェーズ2・Android の自動入力)

実機(XIG05)での確認は、利用者が自分の端末で行う。精査(Opus)を通ってから、APK を実機に入れる。
実在のパスワードは使わない。以下は架空の項目だけで確かめる。

## 準備

1. APK を入れる(PC の開発環境から。`~/pwvault-build/app/outputs/apk/debug/app-debug.apk`)。古い APK が入っているときは先に消す。
2. 実機の Tobari に残したい保管庫があるときは、先に設定画面から .kdbx を書き出して控えておく。確認専用の保管庫では同期の設定をしない(本体の保管庫の行に書き込まないため)。
3. Tobari を開き、確認専用の保管庫を使う(本体の保管庫に架空の項目を足さない)。新規作成するか、エミュレーター用の架空の保管庫を取り込む(`PWV_EMU_VAULT_DIR` を指定して `EmulatorVaultTest` を実行すると `emulator-vault.kdbx` ができる。マスターパスワードはテストのソースの `MASTER`)。
4. システムの設定 → パスワードとアカウント(機種により「パスワード、パスキー、アカウント」)→ 自動入力サービス で Tobari を選ぶ。設定画面の「自動入力」の欄の「自動入力の設定を開く」からも開ける。
5. Chrome の設定 → 自動入力サービス → 「別のサービスを使用して自動入力」を選ぶ(Chrome の再起動が要る)。

## 架空の項目(Tobari に作る)

| タイトル | 種類 | ユーザー名 | パスワード | URL / パッケージ名 |
|---|---|---|---|---|
| 確認用アプリ | パスワード | app-user | 本体用の目印(AGENTS.md)+ `-app` | Android のパッケージ名に、確かめるアプリのパッケージ名 |
| 確認用サイト | パスワード | page-user | 本体用の目印 + `-page` | URL に、確かめるサイトのホスト(例: `https://example.com`。自分で管理するテストページでもよい) |
| 隠れる API キー | API キー | key-user | 本体用の目印 + `-key` | 上の2つと同じ URL とパッケージ名 |

## 確かめること

1. アプリ1つ: 確かめるアプリのログイン画面でユーザー名の欄を押すと、「確認用アプリ」だけが候補に出る(「隠れる API キー」は出ない)。選ぶとユーザー名とパスワードが入る。
2. Chrome のサイト1つ: 確かめるサイトのログイン画面で同じく候補が出て、選ぶと入る。Chrome の候補にも「隠れる API キー」は出ない。
3. ロック: Tobari をロックした状態で欄を押すと、「ロックを解除して入力」だけが出る(項目名は出ない)。押して解除すると候補に変わり、選ぶと入る。
4. 一致しないとき: 登録していないアプリやサイトでは候補が出ない。
5. 保存: 新しい架空のユーザー名とパスワードで送信すると、保存の確認が出る。確認の画面で「保存」を押すと、一覧に種類がパスワードの項目として出る。「キャンセル」では書かれない。
6. 自動ロック: 設定で自動ロックを 1 分にし、Tobari を離れて 1 分以上たってから欄を押すと、「ロックを解除して入力」になる。
7. 設定画面の「自動入力」の欄が状態を示し、無効なときはボタンでシステムの設定が開く。保存先と取り込み元を選ぶ画面も開ける。

## 後片付け

- 架空の項目を消す。確認専用の保管庫を使った場合は、アプリの保管庫を元に戻す。
- カナリアの確認は、実機では行わない(エミュレーターで実施済み)。
